# 运维工具集 —— 扩展清单与功能规划

> 定位：在现有「1 个集成平台 + 3 个被纳管工具」基础上，补齐一套**开箱即用、零/低依赖、内网可用**的完整运维工具链。
> 目标：**尽量少装环境（优先标准库 + 复用系统命令），把高频运维动作全部收敛到浏览器一个入口。**

## 二、统一设计约定（每个新工具必须满足）

新增工具一律按下列规范实现，才能被平台无感接入，也才能保持"少装环境"：

1. **依赖优先级**：标准库 > 调用系统自带命令（`ssh`/`ss`/`lsof`/`ps`/`du`/`jstat`/`mysqldump`）> 纯 Python 单文件库 > 有 pip 依赖（必须可降级）。
2. **双版本兼容**：Python 2.7.5+ / 3.7.5+ 均可直接运行（复用统一兼容层）。
3. **命令行参数**：`--host --port --token --pidfile --work-dir`；同名环境变量兜底。
4. **标准接口**：`GET /api/ping`、`/api/health`、`/api/status`，统一返回 `{"status":"success"|"error", ...}`。
5. **鉴权**：`X-Auth-Token` 头 + `?token=` 双通道；`--token` 为空时打印醒目安全告警。
6. **页面分离**：`templates/<tool>.html` + 占位符 `{{version}}`，按 mtime 缓存，改完刷新即生效。
7. **接入方式**：默认以「平台内新视图」形式注册（不额外占端口）；同时保留独立启动能力。
8. **审计留痕**：任何有副作用的操作（写/删/执行/发布）必须向审计中心推一条记录。

**建议新增公共模块 `opslib/`**（放 `ops_tools/` 根下，各工具 `sys.path` 引入）：

```
ops_tools/
├── opslib/                     公共库（替代 4 份重复兼容层）
│   ├── compat.py               py2/py3 兼容工具函数（to_bytes/is_within/disk_usage...）
│   ├── server.py               ThreadingHTTPServer + 路由 + 静态资源 + CORS
│   ├── auth.py                 统一 Token 校验、客户端 IP、登录会话
│   ├── apibase.py              标准 /api/ping|health|status、统一 JSON 响应、错误码
│   ├── httpx.py                轻量 HTTP 客户端（带连接池复用、超时、重试）
│   ├── probe.py                主机指标采集（读 /proc、ps、df、ss，零依赖）
│   ├── audit.py                审计写入（追加日志 + 哈希链防篡改）
│   ├── task.py                 异步任务队列 + 进度上报 + 取消
│   ├── sse.py                  Server-Sent Events 推流（实时日志/进度/曲线）
│   ├── notify.py               通知渠道（SMTP 邮件 / 企微·钉钉·飞书 webhook / syslog）
│   └── crypto.py               AES/口令派生加密（凭据保险箱用，标准库 hashlib+自实现或纯 py 单文件库）
├── tools/                      被纳管侧轻量服务
└── platform_console/           管理机侧控制台（含 static/ 前端）
```

## 四、现有工具的增强点

### 4.1 管理平台 `ops_Platform.py`
- 新增视图：**监控看板 / 日志查看 / 任务中心 / 发布中心 / 审计 / 资产台账**（保持「平台不落地、不执行」的边界，均通过转发或探针接口实现）。
- 服务器**分组 + 标签 + 环境**（生产/测试）、批量勾选多机执行、按标签批量操作。
- **实时通道**：日志、命令输出、上传进度、监控曲线改用 SSE，替代轮询。
- 多用户与角色（只读/运维/管理员）、按服务器授权。
- 开放 API（Token + OpenAPI 描述）便于 CI/CD 调用。
- 界面：暗色主题、移动端适配、快捷键、命令面板。

### 4.2 `upload_server.py`
- 回收站（删除可还原，见 B6）、目录级打包下载、在线编辑小文件（带备份）。
- 秒传（哈希指纹命中直接落地）、上传限速、单机并发上限与配额。
- 目录树浏览（当前偏列表）、按类型/时间筛选排序。

### 4.3 `web_shell.py`
- 持久 shell 会话（避免每条命令重新 spawn），支持 `cd` 等有状态命令。
- 命令分组收藏/模板（复用 C5）、结果导出（txt/csv）、录制回放（复用 H2）。
- 结构化结果解析（如 `df`、`ps` 输出转表格）。

### 4.4 `diff_file_dir_jar_excel.py`
- 三向比对（基线 / 版本 A / 版本 B）、差异导出为补丁或报告。
- `.docx / .pptx` 结构化内容比对（当前仅二进制摘要）。
- 忽略规则可视化配置、比对结果持久化与历史查询、批量目录比对。

## 七、风险与注意事项

1. **安全默认值**：所有工具默认无鉴权 → 启动时必须打印醒目告警；建议默认生成随机 Token 并要求显式 `--token ""` 才可关闭。
2. **删除/发布类操作**：一律「预览 → 二次确认 → 可回滚」，删除进回收站，发布前做配置快照。
3. **审计不可绕过**：审计写入在平台层完成，即使探针被直接访问，平台侧操作也有记录。
4. **依赖降级**：`flask/openpyxl/paramiko` 等一律作为可选依赖，缺失时功能降级而非启动失败（沿用 diff 工具现状）。
5. **命令白名单粒度**：批量执行与脚本库会放大白名单风险，建议按"工具 + 目标机标签"双重限制。
6. **留存策略**：日志、录像、备份、审计均需可配置的保留期与磁盘上限，避免工具自己把磁盘撑满。
